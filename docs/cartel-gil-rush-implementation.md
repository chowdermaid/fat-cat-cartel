# Cartel Gil Rush

Cartel Gil Rush replaces Ladders & Backstabbers at `/cartel-gil-rush`; the old URL redirects. The existing Boss/Underpaw access gate, app shell, Game / Rulebook tabs, themes and reduced-motion view transitions remain. Hosts share one current event through Firebase. It is not an interactive player board.

## Host workflow

1. Open Add players. Choose roster members, including Friends, or add guests. Guest names can be edited before starting; roster names/avatar URLs are snapshots. Names are normalised, case-insensitive duplicates are rejected, and names are limited to 80 characters.
2. Randomise order & start requires at least one player, shuffles once, locks participants, and sets round 1. Mood selection is optional.
3. Read the fixed, numbered avatar/name list in the left rail on desktop or horizontal strip on mobile. It never selects or advances a player. The host calls turns and skips finished players externally.
4. Use the Board mood dropdown to choose No mood, Lucky Sixes, Underdog Bonus, Push Your Luck or Workers' Compensation. Selection applies immediately at any round. Game shows names without colour labels and only the main explanation matching Rulebook Board moods, including its shorter red rule. Extra mood details and the standalone round/host note are removed. Colours and internal mood IDs remain. Rulebook retains its round-4 guidance, but Game does not enforce timing or duration.
5. During play, compact labelled chevron buttons change only the round. Click Round N for direct corrections. Values must be positive safe integers; setup remains round 1. The setup start explanation is omitted.
6. Each live player row is a keyboard-accessible gil-edit trigger, showing their saved total beneath their name with coin/edit icons. Clicking opens a side popover with the Gil won input and Save command; small screens use collision-aware positioning. Save or Enter replaces the total and closes the popover only on success. Totals start at zero, accept non-negative safe integers and allow downward corrections. No automatic payouts or gil sorting occur. Dirty drafts survive closing/reopening the popover and live updates, with the latest saved total shown in the editor. Stale saves retain the draft and require an explicit Retry after review. Player-panel padding matches Rulebook navigation (`pl-2 pr-1 py-2`). The redundant View players command is removed during play; setup's lazy mounted player dialog remains.
7. Reset through the confirmed overflow action to change participants or begin another event. It clears the shared event, including gil, for every host, with no undo.

Movement, dice, challenges, finishing places and reward choices stay with the host. The website records only manually entered per-player gil totals and has no current-player state, turns-remaining counter, automatic mood sequence, interactive gameplay board, action log or team/card/mission state. Rulebook provides five reference chapters, beginning with a read-only Board Overview; its content, navigation, artwork and credit are unchanged by the shared-event work.

## Feature structure and storage

`src/features/cartel-gil-rush` follows the existing feature layout: thin route export, feature types/constants/presentation, pure event operations in `utils`, persistence/view animation in `hooks`, and game/rulebook components. Tiles & movement now presents compact icon/name/effect rows for Shark, Moogle, Mushroom, Ladder, Red arrow and Crown/finish. Fatcat and Chocobo use the same icon/name/effect rows as the other tiles, between Mushroom and Ladder. The cream `TileCard` component and full tile definitions remain available for later work.

Both Game and Rulebook use the same two-row header: The Meowfia branding, event title and Draft label above a consistent tab row. Only contextual actions and the selected tab change; header geometry and branding do not switch layouts. Host dialogs remain mounted when hidden by Rulebook, preserving their state and avoiding extra roster reads. Game retains its static roster rail, mood banner and illustrated quick references. There is no current-player highlighting, turn progression or remaining-turn counter. The existing global app sidebar remains available; mobile keeps player order horizontally scrollable.

Rulebook is one continuous document containing five chapters (Board Overview, Quick start, Tiles & movement, Board moods, Rewards), rendered once from separate content components. The shared header remains stationary; a bounded right-hand `ScrollArea` owns reading scroll. Rulebook fills the viewport below the 48px app toolbar, with the flex layout allocating the remaining height beneath the actual event header. These constraints apply only to Rulebook; Game retains its existing page scrolling. The left navigation is 56px with labelled/tooltip-equipped icons below 640px, 180px from 640px, and 220px from 1050px of workspace width. Its own `ScrollArea` keeps links reachable on short screens. There is no mobile chapter dropdown and no chapter-level tabs or Previous/Next buttons. A feature-scoped block override on the reading viewport's Radix content wrapper prevents its default table sizing from widening the document to the board's minimum width.

Navigation links target stable `rulebook-` anchors without changing the URL/hash. Explicit navigation focuses the chapter heading without scrolling ancestors and scrolls the reading viewport with a 16px inset; reduced motion uses immediate movement. `useRulebookScroll` highlights the last heading crossing a line 24px below the viewport top, with Rewards selected at the bottom. Passive scroll updates use one animation frame; viewport/content resize observers recalculate positions. Tracking pauses while Game is visible. The saved reading offset and active chapter survive switching views in memory; refresh starts at Board Overview. DOM listeners/observers and pending frames are cleaned up. No event persistence, auth, asset or Firebase operations changed.

Board Overview uses `boardData.ts` for the authoritative 24 special placements and eight connections. `utils/board.ts` generates all 90 cells in ascending DOM order and calculates a six-row, fifteen-column serpentine grid, from 1 at bottom-left to 90 at top-left. Tile 78 is a neutral white tile with no symbol. The ladder starts at tile 14 and ends at 45; tile 13 is only the destination of the fall from 74. Ordinary rows alternate slate grey (#696664) for 1–15, 31–45 and 61–75, and snow white (#F2EFE7) for the other rows. Special roles override the row colour: turquoise sharks, plum mushrooms, ochre moogles, orange chocobos, golden Fatcats, lime ladder endpoints, crimson fall sources and a gold finish. White or dark 12px numbers contrast with each face. The centred board uses compact square panels and the default website background through its gutters; there is no outer frame, subtitle, caption, destination dots or visible route controls. Supplied character artwork and the library crown remain. Theme-aware angular arrows outside the panels show the serpentine path. The symbol legend remains below. The canvas is 840–1200px wide; its nested `ScrollArea` owns horizontal panning while vertical wheel scrolling continues through the reading pane. There are no player pieces or movement controls.

`useBoardGeometry` measures endpoint centers relative to the canvas through a resize observer, coalesced into one animation frame. Panning moves the SVG and cells together. The SVG draws straight lime rails with evenly spaced rungs and straight red fall shafts with open V-shaped arrowheads, above tile backgrounds and below numbers/artwork, with pointer events disabled. Structural endpoints are inset 16% of a cell from the measured centres along each route. Restrained darker strokes shade the connectors. Only origin tiles are buttons, labelled with their source/destination and pressed state. Selection highlights endpoints and dims other routes; pressing Escape or clicking the same route again restores the all-routes view. A screen-reader-only status announces selection. Route chips, visible counters and Clear selection were removed at the user's request. State is temporary and local to Board Overview, survives view switching, and never touches the event controller or storage. Measurement stops and pending frames are cancelled while Rulebook is inactive or unmounted.

Quick start begins with Finishing directly below its chapter heading: "The first three to reach the crown can choose a prize. Game stops after 3 finishers". The former subtitle, standalone violet example and footer/fixed-order note are removed. The numbered steps and round-4 mood notice remain. Its separate Board moods summary remains removed. Headings remain at 28 to 32px, body copy at 14 to 16px, step badges at 40px and mood icons at 48px. Chapter boundaries use consistent spacing and subtle top borders. Future artwork is user-supplied or a labelled placeholder; no image generation.

Tiles & movement keeps its 40px artwork slots and divided reference rows. The amber non-chaining notice, challenge landing note and movement-note list are removed at the user's request. Names and effects stack within each row on narrow screens. `tileArtwork.ts` shares the user-supplied shark, moogle, mushroom, chocobo, ladder and red-arrow SVGs between these rows and Game's 56px quick-reference slots. Fatcat uses the supplied `cartel-gil-rush/fat-cat.svg` across Game quick references, Board Overview, its legend and Tiles & movement. The mushroom placeholder is removed. Crown/finish retains its library icon because no matching asset was supplied. Five supplied files contained SVG markup with `.png` names; their extensions were corrected to `.svg` without changing their content. No new images are generated.

Shark now grants a standalone `/random 10` tile roll. An even result moves forward by that amount; an odd result moves backwards by that amount. Movement remains bounded by the start and tile 90, does not chain, and receives neither a violet attempt nor Lucky Sixes payout. Forward shark movement may reach the finish. The Game quick reference, Rulebook summary, shared tile-card definition and tile-roll notes all use this rule, replacing the former fixed three-space setback. Movement remains host-managed.

Board moods uses four compact bordered cards with yellow, blue, violet and red tinted surfaces and spacing between cards. Titles contain only the mood names, with no separate colour labels. On narrow screens, rules use the full card width below the icon/name. It says "Begins from round 4" and retains the three-individual-turn duration. Only the main mood rules and two compact violet movement examples appear; secondary explanations, exclusions, the larger examples table and suggested host-selection paragraph are omitted from this chapter. Full mood definitions remain in the shared constants used by Game. The supplied underdog, push-your-luck and workers-compensation PNGs are shared by Game and Rulebook through `moodArtwork.ts`. Lucky Sixes retains its existing dice presentation. No artwork is generated.

Fatcat/Chow's Deathroll and Chocobo/Axo's Trivia use the exact same divided icon/name/effect rows as Shark, Moogle and Mushroom, directly after Mushroom and before Ladder. Their procedures and 200,000-gil success/no-payout outcomes remain as row text. The standalone challenge-card component and the trailing one-attempt-per-landing note are removed.

Rewards contains the Grand prizes heading, finish-order selection wording and three muted FFXIV item panels marked To be announced. The earned-gil reminder is removed. First picks first, second picks next, third receives the remaining prize. The requested turn-confirmation, host-announcement and separate payout/revisit paragraphs remain removed. The chapter ID/anchor is rewards, and Rewards owns its content. No digital prize selection or backend calls are added.

`RuleText` decorates the visible Quick start, tile and mood reference text with inline Lucide dice, directional movement arrows and the existing Coins icon used elsewhere in the site. Six-sided commands/natural sixes use Dice6; other roll references use Dices. Violet examples show matching Dice2/Dice5/Dice4 faces. Icons are hidden from assistive technology while the original words/amounts remain readable.

The scroll hook exposes the measured reading viewport height as a feature-local CSS variable. Rewards receives a minimum chapter height based on that value, so both final chapters can scroll their headings to the 16px navigation inset instead of sharing a clamped bottom position. The normal passive tracking, bottom behavior, focus, reduced motion and view-switch restoration remain intact. Resize updates the value only when needed.

The active record is `/events/cartelGilRush/current`: version 1, monotonic revision, setup/live phase, ordered player snapshots with `gilWon`, nullable mood and positive-integer round. Live events require players, but not a mood. Setup round is always 1 and gil totals are zero. IDs, normalised names and optional roster IDs remain unique. Null mood and empty player arrays omitted by RTDB are normalised on read.

`useSharedEvent` subscribes once while the authorized workspace is mounted, including across tab switches. The feature API imports DB helpers only from `src/lib/db.ts`. `mutateCartelGilRushEvent` revalidates the linked Boss/Underpaw session before any mutation. Each atomic transaction requires the expected revision; stale actions, double starts, imports over occupied events and stale resets fail without overwriting newer state. Reset increments revision instead of deleting the record. Snapshots/replies are merged by revision, same-browser mutations are serialized and stale callbacks after unmount are ignored. UI state commits only from confirmed cloud snapshots or successful callable replies; failures retain drafts and never queue automatic retries.

The SDK-independent model in `functions/src/cartel-gil-rush-model.ts` is shared by the Functions service, feature API and browser fixtures so validation and transitions match without duplicating them. Its browser imports contain no Admin SDK or credentials. The server whitelists public event/player fields and does not store tokens or Discord session identities in the public record.

The existing `fcc_cartel_gil_rush_event_v1` key, version-1 schema, legacy parser and save remain unchanged. A valid old save can be explicitly imported only into an empty shared event, preserving phase/order/round/mood and initializing gil to zero. Import does not modify the original save and cannot overwrite a concurrent host's changes. The older `fcc_ladders_and_backstabbers_event_v1` is neither read nor modified. There is no automatic local fallback when Firebase fails. Stub/persona mode uses a separate `fcc_dev_data_cartel-gil-rush` record with Web Locks and storage events for atomic cross-tab fixture updates.

Tile 1 is a visual start landmark: it shares tile 90's gold face and dark ink, with a Lucide flag instead of the crown. Its starting arrow and the caption "Start here, moving horizontally across" use gold in dark mode and amber in light mode. The caption sits below the arrow inside the horizontally scrolling canvas, with balanced wrapping on phones. This does not add a gameplay effect or change the 24 special placements.

## Data and cost

The roster loader mounts on first opening player setup and remains mounted through setup, even while the dialog is closed. Starting unmounts it. It reuses `useMembers`: one `membersLastUpdated` read per mount and a `/members` download only when the shared three-hour cache is stale or mismatched. React Strict Mode may remount effects during local development. Displaying roster avatars adds ordinary image downloads. Saved events render from snapshots without loading the roster. Guests and failed images show initials.

Event data is publicly readable like Easter's scoreboard; direct client writes are denied. Each authorized workspace adds one small live event subscription and downloads changes as hosts save. Each action adds one protected callable, existing session/link/member and Discord role validation, a small event read to warm the server transaction cache, and one atomic transaction. A short-lived server value listener holds that cache through the transaction and is always detached afterward. Contention can retry transaction reads. No polling, scheduled Functions, history or growing logs are added. Roster reads remain unchanged. No environment files or new secrets are changed.

Deploy the `mutateCartelGilRushEvent` Function and database rules before releasing the frontend; deployment is separate from implementation. Existing Discord configuration and bot secret are reused. The shared record remains until confirmed Reset, with no TTL or scheduled deletion.

Tile references use seven user-supplied SVGs, including the approximately 2.5KB Fatcat SVG, bundled by Vite and reused across Game/Rulebook. The existing dice PNG remains used by the Game mood banner. These are ordinary frontend assets with no Firebase data or Function operations. Current asset mapping and historical provenance are in [visual assets](cartel-gil-rush-visual-assets.md).
